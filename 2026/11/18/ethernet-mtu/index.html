以太网的 MTU

2026-11-18 / 计算机网络 / #以太网 , #MTU , #交换机 , #路径 MTU / 阅读 -

Maximum Transmission Unit

假设两台电脑接在同一台交换机上，电脑 A 要给电脑 B 传一个文件。网络不会把整个文件当成一块数据塞进网线。以常见的 TCP 文件传输为例，发送端把文件内容分成许多小段，分别封装成 IP 包，再一个包一个包地发出去。

MTU 是一段网络链路一次能承载的数据单元的大小上限。 在这里，这个数据单元就是 IP 包。电脑 A 的以太网接口如果设为 MTU 1500，就表示它通过这个接口发送的单个 IP 包最多可以有 1500 字节。文件可以比这大得多，因为它会用多个包来传。MTU 也不是网速：网速说的是一秒能传多少数据，MTU 说的是每个包最多能有多大。

MTU 与以太网帧长度

IP 包带着源 IP、目的 IP 等信息，但网线上实际传输的是以太网帧。发送端把 IP 包放进帧的数据区，再在外面加上以太网自己的信息。比如帧头有目的 MAC 地址，用来告诉局域网这一帧要交给哪个设备；帧尾有校验值，用来检查帧在传输中有没有出错。

局域网里的帧转发

回到电脑 A 给电脑 B 发数据的例子。假设两台电脑在同一个以太网局域网里，A 把 B 的 MAC 地址写进帧头。交换机收到帧后，用目的 MAC 地址查自己的转发表。如果表里已经记录了 B 接在哪个端口，就把帧往这个端口发。它不需要打开里面的 IP 包来决定往哪儿转发，也不会替两台电脑把一个太大的 IP 包切成几个小包。

这就解释了为什么开了巨帧，也就是允许比标准以太网帧更大的帧，不能只看两端的网卡。比如 A 和 B 的网卡都能处理装有 9000 字节 IP 包的帧，但中间的交换机只支持标准大小：A 可以把帧发到交换机，交换机却不会把这么大的帧转发给 B。两端支持的上限再大，也不能代替中间设备的转发能力。

更大的帧能让同样多的数据用更少的帧来传，减少重复的帧头和处理次数。但它不会把网口的传输速率变快，而且要让沿途设备都能处理相应大小的帧。

链路 MTU 与路径 MTU

现在把 B 挪到另一个网络，中间加一台路由器。A 还是从 MTU 为 1500 的以太网发出一个 1500 字节的 IP 包，但路由器通往 B 的下一段链路只允许 1400 字节。

路由器和刚才的交换机做的事不同。A 发出的帧只负责把 IP 包送到路由器。路由器取出里面的 IP 包，根据目的 IP 地址选下一段链路，再按那段链路的要求重新封装。问题就出在这一步：上一段装得下 1500 字节，下一段只装得下 1400 字节。 换一层帧头，并不会让里面的 IP 包变小。

超出的部分怎么办，要看 IP 版本。IPv4 在允许分片时，路由器可以把一个大 IP 包拆成几个较小的 IP 分片，由接收端重新拼起来。如果包标明不许分片，路由器就丢弃它，并向发送端报告下一段放不下。IPv6 路由器不负责分片，遇到这种情况会丢包并发送 Packet Too Big 通知，告诉发送端把后续包发小一些；如果确实需要分片，也由发送端做。

路径 MTU 是一个 IP 包从起点到终点、不经分片就能通过的最大尺寸。 在这个例子里，两段链路分别允许 1500 和 1400 字节，所以路径 MTU 是 1400。发送端不必知道每段链路的配置，可以根据路由器返回的通知调整发包大小，这就是路径 MTU 发现的基本思路。

一段链路的 MTU 回答“我能往下一站放多大的包”，路径 MTU 回答“这个包原样能不能走完全程”。前者是本段的限制，后者由整条路径上最小的限制决定。
