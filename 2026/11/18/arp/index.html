ARP 地址解析

2026-11-18 / 计算机网络 / #以太网 , #ARP , #IPv4 , #MAC 地址 / 阅读 -

ARP（Address Resolution Protocol，地址解析协议）用来在本地以太网上，根据已知的 IPv4 地址查出对应的 MAC 地址。 比如，电脑知道办公室打印机的 IP 是 192.168.1.50，但还不知道它的 MAC，就可以用 ARP 发出询问。打印机收到后，把自己网卡的 MAC 地址回复给电脑。

这里用到两种地址，因为发送数据要做两件事。目的 IP 地址写在 IP 包里，指明这个包最终要送到哪里。要让这个包在办公室的网线上传输，电脑还得把它装进一个以太网帧。帧是以太网收发数据的单位，开头有一个单独的地址栏，叫目的 MAC 地址，指明这段以太网上该由哪个网络接口接收这一帧。

发给本地打印机时，这两个地址都指向打印机；发给外网服务器时，它们指向的却不是同一台设备。先看打印机。

同一子网：查询打印机的 MAC

假设电脑和打印机接在办公室的同一台交换机上。交换机连接着多台设备，负责把从一根网线收到的帧转发到相应的网线上。两台设备也在同一个 IP 子网内：在这个例子里，电脑的网络配置把打印机所在的一段 IP 地址划为本地，可以直接发送，不用先交给连接不同网络的路由器。

你点下打印时，操作系统先用打印机的 IP 查这台电脑自己的路由表。这张表记录了去不同目的网络该从哪个接口发、是直接发还是交给路由器。查表的结果是“从有线网卡直接发给打印机”。到这一步，电脑已经选好了接收者，接下来才需要它的 MAC。

接下来，电脑查看自己的 ARP 缓存，也就是这个接口上最近学到的 IP 与 MAC 对应关系。假设这是第一次打印，里面还没有打印机的记录。

  1. 电脑广播询问。 广播就是不单独指定一台接收设备，而是让同一本地网络里的设备都收到。电脑单独发出一帧 ARP 请求，目的 MAC 填以太网约定的广播地址 ff:ff:ff:ff:ff:ff，请求里写的是：“谁的 IP 是 192.168.1.50？请把你的 MAC 地址告诉我。”请求还带着电脑自己的 IP 和 MAC，方便对方回复。
  2. 打印机直接回复电脑。 交换机把这帧广播转发出去。能收到同一份以太网广播的范围叫作广播域；请求不会经由路由器传遍互联网。办公室里其他电脑收到请求，看到问的不是自己的 IP，不作应答。打印机看到问的是自己，就把自己的 MAC 写进应答。它从请求里已经知道电脑的 MAC，所以这次可以只回给电脑。
  3. 电脑发送打印数据。 电脑记下这条对应关系，把打印机的 MAC 填入新帧的帧头，再把原本要发的 IP 包装进去。刚才的请求和应答都没有携带打印数据；直到这个数据帧发出去，打印数据才真正上了网线。

一份文档往往要分成许多包。只要缓存里的记录仍然有效，后续的帧就可以直接使用这个 MAC，不必每发一帧都问一次。记录也不会永远有效：打印机换了网卡，即使 IP 没变，旧 MAC 也可能不再适用。

电脑用 ARP 缓存里的「IP → MAC」记录把帧头填好。交换机收到帧后，再用自己的转发表查「MAC → 端口」，决定从哪个网线接口把帧送到打印机。

跨子网：查询网关的 MAC

现在，电脑改为访问互联网上的服务器。它查的还是同一张路由表，但这次的结果不同：服务器不在本地子网，包要先交给办公室的路由器。路由器连接办公室网络的那个接口，就是电脑使用的网关，假设地址是 192.168.1.1。

如果缓存里没有对应记录，电脑广播问的是“谁的 IP 是 192.168.1.1”，而不是“谁的 IP 是远程服务器的 IP”。远程服务器收不到办公室里的以太网广播，也不需要收到。电脑此刻要做的，只是把包送到路由器手上。

从电脑发出的数据 IP 包的目的 IP 以太网帧的目的 MAC
发给本地打印机 打印机的 IP 打印机的 MAC
发给远程服务器 服务器的 IP 本地网关的 MAC

收到第二种帧后，路由器取出里面的 IP 包。现在轮到路由器用目的 IP 查路由器自己的路由表，决定下一步往哪里发。如果下一段也是以太网，它会为那一段重新封装帧。网关的 MAC 完成的是第一段交付，不会跟着包一路传到服务器。

这也解释了一个容易忽略的现象：假设你先打开外网的新闻网站，再连接另一台远程服务器。两个目的 IP 完全不同，但只要路由都指向同一个网关，而且电脑还缓存着网关的 MAC，第二次连接就不用为新服务器再广播一次。反过来，即使你事先知道远程服务器的 MAC，也不能把它填进办公室里的帧头来跳过网关。这个地址不能告诉办公室的交换机，去另一张网络该走哪条路。

ARP 的工作原理

ARP 能工作，是因为以太网提供了两种不同的交付方式：不知道对方的 MAC 时，可以先广播，让本地设备都听到问题；知道 MAC 后，就可以把后续数据单独发给对方。ARP 把广播得到的答案暂存在发送端，让一次询问能服务于后续多次发送。RFC 826 定义了这套请求与应答机制，RFC 1122 §2.3.2 说明了主机对缓存记录的管理要求。

路由选出的、在当前链路上直接收包的设备，叫作下一跳。ARP 查的是下一跳的 MAC。打印时，下一跳就是打印机；访问外网时，下一跳是本地网关。这也是为什么电脑不需要知道远程服务器的 MAC，就能把数据发给它。
